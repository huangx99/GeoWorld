# GeoWorld 离线成果演示

> 状态：已完成 | 开始日期：2026-08-11

## 目标

把 M1～M3 的世界对象、2.5D 空间、规则、AI、命令缓冲和确定性能力组合成客户可以直接观看的离线成果。

## 演示场景

### 三维园区疏散

- 一栋三层园区建筑；
- 一台温度异常设备和多名人员；
- 设备过热触发报警规则；
- 烟雾按预定事件扩散到相邻楼层；
- 人员 FSM 从工作切换为疏散，并沿楼层、楼梯和室外路线到达安全点；
- 每个 tick 记录对象状态、楼层位置、事件和最终状态 hash。

页面以可旋转、可缩放的三维剖视建筑显示三层楼板、楼梯、烟雾楼层和人员的垂直移动，不再把楼层拆成互不关联的二维平面。

### WGS84 战场推演

- 使用一个明确标注为虚构演习区的 WGS84 原点；
- 实际生成并批量更新 200,000 个实体，双方各 100,000 个；
- 接敌后以确定性的成对火力解析执行射击、命中、伤害和阵亡，不只做编队平移；
- 战场回放固定 120 Tick；每个实体拥有由种子决定的随机生命、攻击和防御战力，战损会逐步展开而不会在开场后立即清场；
- 每个战斗 tick 记录双方存活数、累计射击、累计命中和累计损失；
- 使用 WGS84 → ECEF → ENU 的全局/局部坐标链路，并展示经纬度、ECEF、ENU 和 Cell；
- 后端记录实体生成耗时、120 Tick 批量更新耗时、吞吐量、空间 Cell 数和确定性 hash；
- 离线页面使用浏览器原生 WebGL2 单批次绘制 200,000 个点，并显示实时 FPS；
- 页面只内嵌确定性生成参数和抽样坐标，避免为每个 tick 重复存储 200,000 份 JSON 对象。
- 每个实体的阵亡 tick 以紧凑字节数组内嵌，页面据此停止阵亡实体并显示交火线、命中闪光和战损变化。

## 交付形式

`geoworld-showcase` 在本地生成：

- `showcase-run.json`：版本化回放数据；
- `showcase.html`：内嵌同一份数据的自包含网页。

浏览器直接打开 HTML 即可播放，不使用 HTTP 服务、WebSocket、CDN 或任何外部网络资源。

## 页面能力

- 三维建筑旋转、缩放和全楼层疏散轨迹；
- 播放、暂停、逐 tick 和倍速；
- 人员、设备、危险区域和安全出口可视化；
- 事件时间线和选中对象详情；
- 安全人数、疏散人数和最终状态 hash 汇总。
- 园区疏散/战场推演场景切换；
- 20 万战场实体批量渲染、经纬网和坐标抽样；
- 战场接敌、火力交换、阵亡状态和双方战损回放；
- 后端吞吐量与前端实时 FPS 展示。

## 非目标

- 不实现生产级地形、模型材质和军事仿真算法；
- 不实现实时网络同步；
- 不实现完整导航网格，疏散场景使用确定性预定义三维路线；
- 不把演示专用 UI 或场景数据放进世界运行时核心。
- 战场仅用于展示大规模实体、空间坐标和回放技术，不表达现实地点、现实组织或现实事件。

## 验收标准

- 单个命令生成 JSON 和自包含 HTML；
- 页面在断网环境下可直接打开和播放；
- 所有世界状态修改仍经命令缓冲；
- 同一场景重复运行得到相同最终状态 hash；
- 三维园区中能连续观察人员跨楼层并离开建筑；
- 战场场景实际批量生成和更新 200,000 个实体，页面实体计数必须来自生成结果；
- 战场回放必须能看到交火过程，页面存活/损失统计必须来自后端逐 tick 结果；
- 坐标抽样能同时核对 WGS84、ECEF、ENU 和 Cell；
- WebGL2 可用时用一个绘制批次显示全部实体，不为 20 万实体创建 DOM 节点；
- 默认构建和测试保持通过。

## 运行

```bash
cmake --preset default
cmake --build --preset default --target geoworld-showcase
./build/default/geoworld-showcase
```

生成后直接打开 `build/showcase/showcase.html`。

当前园区场景生成 25 个 Tick、12 名人员、3 个危险楼层；战场场景生成 121 个回放帧并批量更新 200,000 个实体。两者重复运行都必须得到相同最终状态 hash。
