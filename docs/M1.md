# M1：世界内核

> 状态：已完成 | 完成日期：2026-08-11

## 目标

交付一个不依赖客户端和数据库、能够确定性推进的最小可计算世界。M1 冻结后续模块共同依赖的身份、对象、schema、时间、写入和诊断接口。

## 有什么用

- 为任意领域对象提供稳定的全局身份和七要素语义表达；
- 为 ECS、空间、AI、规则和持久化提供不随三方库变化的公共边界；
- 用固定逻辑帧和种子随机数建立回放与 what-if 推演的确定性基础；
- 用命令缓冲统一写入，使后续并行、插件和分布式路由无需改写业务调用方；
- 从第一阶段提供结构化日志、状态 hash 和 Inspector，避免并发及回放问题无法定位。

## 范围

1. `foundation`：WID/RID/FID 强类型、错误与版本基础、确定性随机数；
2. `schema`：组件、对象类型和关系 schema 的注册、查找与版本检查；
3. `world_model`：世界对象七要素、生命周期、关系记录和进程内语义对象仓库；
4. `ecs_runtime`：flecs 集成边界、RID↔WID 映射和最小实体快照接口；
5. `simulation`：固定步长 tick、命令模型、命令缓冲和相位边界提交；
6. `observability`：统一日志接口和核心 tick 指标接口；
7. `debug`：只读 Inspector、确定性状态 hash 和最小 tick 控制接口；
8. `tooling`：资产制品、诊断和 schema 校验的公共接口。

## 非目标

- 不实现空间 Cell、AOI、GIS 导入和流式加载；
- 不实现完整 AI、规则引擎和图形化编辑器；
- 不实现客户端协议、数据库持久化或多进程分片；
- 不在 M1 内完成面向容量规划的性能结论。

## 主要交付物

- 可独立构建的 M1 核心库及公共头文件；
- 一个能创建对象、提交命令并按固定 tick 推进的 `geoworldd` 示例；
- M1 单元测试和最小集成测试；
- flecs/EnTT 真实负载基准框架；
- 工具链资产和调试协议的版本化接口。

## 依赖

- CMake 3.24+、C++20；
- vcpkg manifest；
- flecs 通过 `ecs_runtime` 薄封装接入；
- fmt/spdlog 只允许由 `observability` 适配层使用。

## 风险

- flecs 尚未用 GeoWorld 数据形状验证，需保留 EnTT 对照基准；
- 语义对象字段过早固化可能限制领域扩展，应以 schema 和属性包承接长尾字段；
- 日志、容器迭代顺序和浮点优化可能破坏确定性，状态 hash 测试必须进入 CI；
- 工具链制品格式若未版本化，会使规则、AI 与历史回放失去兼容性。

## 验收标准

- WID/RID/FID 不能隐式互转，RID 能识别代际变化；
- 世界对象能表达七要素并通过 WID 稳定查询；
- schema 重复注册和不兼容版本能被明确拒绝；
- 相同初始状态、命令序列和随机种子产生相同状态 hash；
- 命令在提交前不可见，只在相位边界生效；
- 日志和 Inspector 不改变世界状态；
- CMake 配置、构建和全部测试通过。

## 当前基准

`geoworld-m1-benchmark` 当前只用于建立可复现的相对基线，不作为容量结论。默认 10,000 个语义对象创建并提交命令的单线程样例约为 50–60 ms。

`vcpkg-bench` 使用 Release 构建和相同 ID/位置/字符串组件。100,000 实体样例中，flecs 封装创建约 42 ms、排序快照约 9 ms；EnTT 创建约 7 ms、排序快照约 5 ms。100,000 实体连续执行 10 次位置更新时，flecs system 约 0.9 ms，EnTT view 约 2.7 ms。结果表明 EnTT 创建占优、flecs 批量 System 占优，与 ADR2 的方向一致；它仍是 R1 基线，不能直接替代最终容量规划。

## 验收结论

- 三 ID、七要素对象、schema、固定 tick 和命令缓冲接口已冻结；
- 语义对象层不依赖 flecs，第三方类型未泄漏到公共世界模型；
- 相同输入与随机种子通过确定性状态 hash 测试；
- FlatBuffers 快照具备文件标识、格式版本和 schema 版本校验；
- 默认构建、vcpkg/flecs 构建和 Release ECS 对照基准构建全部通过；
- M1 验收标准已满足，下一阶段开始前必须先创建 `docs/M2.md`。
