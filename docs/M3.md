# M3：规则与 AI

> 状态：已完成 | 开始日期：2026-08-11 | 完成日期：2026-08-12

## 目标

在 M1 的固定 tick、命令缓冲和确定性基础上，建立“事件 → 规则 → 命令 → 世界演化”的第一条可运行链路，为后续 FSM、状态机、行为树和领域插件提供稳定边界。

## 工程价值

- 让世界状态能够由事件和规则持续演化，而不是把业务流程硬编码进核心循环；
- 保证规则动作只能经命令缓冲提交，支持确定性回放和调试；
- 用事件类型、优先级和规则版本建立可审计的执行顺序；
- 为消防、交通、工业等领域插件提供不修改核心平台的接入点。

## 范围

### M3-A：事件与轻量规则

- 确定性事件总线和未来事件表（FEL）；
- 条件表达式的编译后数据结构和类型安全求值；
- 决策表/规则注册、优先级和版本校验；
- 规则动作生成 `simulation::CommandBuffer` 命令；
- 事件、规则和命令的单元及集成测试。

### M3-B/C 批次

- M3-B：Tier1 FSM、Tier2 轻量分层状态机和有界 AI 任务调度；
- M3-C：BehaviorTree.CPP、Lua、纯 C ABI 动态库插件和版本化 AI 制品工具；
- WASM 运行时在插件边界稳定并完成开销验证后接入。
- R5 平台验证：在 Release 构建中以语义等价的最小规则调用测量纯 C ABI、Lua 和 WASM 三条插件边界，记录总耗时与单次调用开销；结果只作为当前机器基线，不外推为容量承诺。

### M3-D：行为编辑工具链内核

- 定义可持久化的行为树和 HFSM 编辑文档模型，文档保留稳定节点 ID、显示名称、布局坐标与运行语义；
- 基于成熟 JSON 库读写编辑文档，不维护自有 JSON 解析器；
- 行为树校验覆盖根节点、节点 ID、子节点基数、父子引用、环路、不可达节点和运行时节点类型；
- HFSM 校验覆盖初始状态、父状态引用、层级环路、转换源/目标、重复转换和不可达状态；
- 从同一份已校验文档确定性导出 Graphviz DOT 和版本化二进制制品；
- `gw-bt`、`gw-st` 支持 `validate`、`dot`、`compile` 和 `inspect`，错误包含稳定诊断码和对象 ID；
- 运行时只加载通过类型、schema、compiler、长度和 source hash 校验的制品；行为树制品可还原为 BehaviorTree.CPP XML，HFSM 制品可构建运行时状态机；
- 文档字段与输出顺序必须稳定，相同输入重复编译产生逐字节一致的制品和 DOT。

#### 平台与领域边界

- GeoWorld 只交付通用规则、FSM/HFSM、行为树、任务调度、脚本/WASM/纯 C ABI 插件骨架，以及行为资产的编辑、校验、编译和加载能力；
- 工具链通过节点注册表接收外部节点类型及其显示名称和子节点基数，不在核心仓库固化消防、战争、交通等领域节点；
- 运行时向领域适配层提供只读 `DecisionSnapshot`、有界 `AiTaskScheduler`、`DecisionIntentBuffer` 和命令缓冲边界，领域实现不得绕过命令缓冲修改世界；
- “索敌、开火、路径规划、疏散”等节点的端口、参数、查询和业务语义由使用方在领域插件中实现，不属于 M3 验收范围；
- 客户演示资产可以消费这些接口，但演示业务逻辑不能反向成为平台核心依赖。

#### M3-D 非目标

- 本批次不实现多人协作、远程资产服务或网页画布；桌面界面必须建立在本批次文档模型和命令行能力之上；
- 不在工具中复制 BehaviorTree.CPP 的执行器或自建 JSON/XML 通用解析器；
- 不在 M3-D 扩展 WASM 沙箱、持久化、客户端接入层或分布式能力。
- 不提供任何行业的行为节点实现、领域参数模型或领域运行上下文。

#### M3-D 依赖

- nlohmann-json 负责编辑文档序列化和解析，json-schema-validator 负责 JSON Schema 结构校验；
- BehaviorTree.CPP 仍是行为树运行时，TinyXML2 复用其依赖，不自建 XML 解析器；
- FlatBuffers 负责编译后的运行时制品，不维护自定义二进制序列化协议；
- Graphviz 负责自动布局与 DOT/SVG 导出；
- Qt 6 Widgets 和锁定版本的 QtNodes 负责中文桌面界面与节点画布，不自建图编辑框架。

#### M3-D 风险

- 编辑文档和运行制品混用会破坏兼容性，因此两者使用不同格式并分别版本化；
- 节点类型扩展可能导致旧工具误接收新语义，因此未知运行节点一律拒绝，编辑器装饰字段允许向前兼容；
- HFSM 的父级回退语义和行为树子节点顺序影响确定性，编译器必须显式冻结顺序并通过重复编译测试。

#### M3-D 验收标准

- 合法行为树/HFSM JSON 能完成加载、校验、DOT 导出、制品编译、制品加载和运行时构建闭环；
- 每类文档至少覆盖重复 ID、缺失引用、环路和不可达对象等失败测试；
- 篡改制品 header、payload 长度或 hash 后必须拒绝加载；
- 相同文档重复编译的二进制和 DOT 完全一致；
- 中文桌面编辑器可往返加载行为树/HFSM，编辑稳定 ID、运行属性和转换，调用 Graphviz 自动布局并编译制品；
- 外部节点描述可通过注册表参与行为树校验，未注册节点仍被稳定拒绝；
- 默认构建和完整 vcpkg M3 构建均通过全部测试。

## 非目标

- 不在 M3-A 实现完整图形化行为树/状态机编辑器；
- 不把规则评估改成 RETE 网络；
- 不让规则或 AI 直接修改世界对象、ECS 或空间索引；
- 不实现客户端协议、WAL/持久化和分布式 authority handoff。

## 依赖

- M1 `foundation`、`world_model`、`simulation`、`schema`；
- M2 空间查询接口作为后续规则预筛选边界；
- M3-C 使用 vcpkg `m3` feature 的 BehaviorTree.CPP、sol2、Lua 和 WasmEdge。

## M3-A 验收标准

- 同 tick 事件按优先级降序、序列号升序确定性处理；
- 事件队列只取出到期事件，未来事件保持顺序；
- 条件表达式支持整数/浮点、布尔和字符串比较；
- 决策表按规则优先级和规则 ID 稳定执行；
- 规则动作只能进入命令缓冲，并在目标 tick 提交；
- 默认构建、vcpkg 构建和全部测试通过。

## M3-B/C 验收标准

- FSM、HFSM 与有界 AI 调度具备确定性顺序测试，复杂决策只能读取快照并输出意图；
- BehaviorTree.CPP、Lua、纯 C ABI 和 WASM 包装均真实加载或调用对应三方运行时，不以内部简化实现替代；
- 纯 C ABI、Lua 与 WASM 使用同一最小规则语义完成可复现 Release 基准，输出调用次数、总耗时和单次开销；
- 插件和 AI 的世界写入最终统一进入 `simulation::CommandBuffer`。
