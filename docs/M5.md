# M5：持久化、恢复、回放与推演分支

> 状态：M5-A～M5-E 实现完成，最终验收未通过（Sanitizer 关闭路径阻塞） | 计划基线日期：2026-08-13 | 开始日期：2026-08-13

## 目标

建立权威世界的本地持久化与确定性恢复闭环，使 `geoworldd` 在进程崩溃、机器重启或计划维护后，能够从最近完整检查点恢复，并重放其后的已持久化输入到最后承诺位置。M5 同时交付历史回放、状态 hash 分叉定位和从检查点创建隔离推演分支的通用能力。

M5 的核心不是把内存世界改成数据库驱动，也不是把每次字段修改都写入事件库。运行时内存仍是唯一权威；WAL、检查点和回放制品只承担耐久承诺、恢复、审计和推演输入职责。

## 产品与工程价值

- 已返回 durable accepted 的外部命令在崩溃后不会静默丢失；
- 服务可以用“最近检查点 + 后续 WAL”恢复，不必从世界创建时刻全量重算；
- 同一初始状态、输入流、随机种子和代码/规则版本能够得到相同逐 tick 状态 hash；
- 回放结果分叉时可通过 hash 检查点二分定位到首个异常 tick；
- 用户可以从历史检查点创建 what-if 分支，替换后续输入或规则版本，而不复制完整世界文件；
- M6 可复用 LSN、不可变检查点、恢复游标和分支标识作为复制与 authority 恢复基础。

## 架构边界

### 模块职责

| 模块 | 职责 | 明确禁止 |
|---|---|---|
| `persistence` | WAL 分段、组提交、检查点目录、恢复计划、回放清单、分支元数据和存储抽象 | 不直接执行业务规则；不绕过命令缓冲修改世界；不依赖 Gateway 或数据库 |
| `world_runtime` | 暴露稳定 tick 边界、可恢复状态提供者、恢复入口和外部输入接纳入口 | 不在 tick 热路径执行文件 IO、压缩或数据库请求 |
| `world_model` / `simulation` / `rules` / `ai` | 提供各自权威或未来状态的版本化捕获与恢复能力 | 不自行创建互不兼容的日志和快照目录 |
| `gateway` | 在返回 durable accepted 前等待持久化接纳结果；使用跨重启幂等键 | 不把 session ID 当作持久身份；不直接写 WAL 文件 |
| `tools/gw-replay` | 检查、校验、恢复演练、回放、hash 对比、分叉定位和分支创建 | 不连接生产 Gateway；默认禁止外部副作用 |
| 存储适配器 | 本地文件系统为 M5 必选实现；未来可接对象存储或数据库归档 | 不改变 WAL、检查点和恢复语义 |

依赖方向冻结为：

```text
foundation + schema + simulation + world_model -> persistence contracts/codecs
persistence contracts                           -> world_runtime integration
world_runtime + persistence                     -> geoworldd
persistence + world_runtime + debug             -> gw-replay
gateway -> durable ingress interface             -> persistence
```

- `persistence` 的公共 API 不出现 gRPC、flecs、FlatBuffers 生成类型、数据库客户端或操作系统文件句柄；
- 文件格式编解码、校验和、压缩、mmap 与具体存储后端都封装在实现层；
- WAL 线程只能接收自有、不可变的规范化输入记录，不能持有世界对象、ECS entity、容器迭代器或请求原始指针；
- 检查点只在稳定 tick 边界锚定；异步编码和落盘不得观察继续变化的可写对象；
- `projection` 快照是客户端视图，`ecs::RuntimeSnapshot` 是当前 ECS 薄投影，二者都不是 M5 权威检查点；
- Gateway session、连接、ticket、FID、ack 基线、发送队列、日志和指标均为临时状态，恢复后重新建立，不进入权威检查点；
- PostGIS、TimescaleDB、TDengine 和对象存储不进入 M5 tick 热路径。本阶段冻结存储接口，只要求本地文件系统闭环。

## 恢复状态模型

### 必须进入检查点的状态

完整检查点必须由注册的 `CheckpointProvider` 集合共同产生，至少覆盖：

- 完整 `world::World` 语义对象，包括七要素、对象版本和内部单调计数器；
- 当前已完成 tick、恢复时的下一 tick、固定 `dt`；
- `CommandBuffer` 中尚未到期的命令、排序序列和 metadata；
- EventBus/FEL 中的未来事件和下一事件序列；
- `DecisionIntentBuffer` 等跨 tick 待处理意图；
- 影响后续演化的 FSM/HFSM/行为树状态、黑板、插件状态；
- 命名随机流的算法、种子和当前位置；
- 活跃规则、脚本、WASM、行为制品和领域 schema 的内容 hash 与版本；
- 已包含的最大 WAL LSN、输入幂等索引和必要的终态回执索引；
- schema registry 指纹、构建兼容标识和状态 hash 算法版本。

任何影响未来演化、但没有注册捕获/恢复实现的有状态模块，都必须使 durable 模式启动失败，不能以默认值继续运行。线程池任务、函数闭包和原始指针不可序列化；这类工作必须在检查点屏障前完成、转换为可序列化意图，或明确声明为可丢弃派生任务。

### 可重建状态

以下状态不写入权威检查点，恢复后由语义世界和配置重建：

- flecs 的本地 RuntimeId 映射和可由语义对象重建的 ECS 派生组件；
- Cell/H3/S2 空间索引及查询缓存；
- M4 ProjectionEngine 的共享历史、连接投影和编码缓存；
- 日志、指标、trace、线程池、socket 和文件映射对象。

如果未来某个 ECS 组件、空间结构或 AI 状态不能由语义对象确定性重建，它必须升级为权威 `CheckpointProvider`，不能继续归类为派生状态。

### 稳定边界

检查点锚点定义为完成 tick `T` 的 Track A/B/C、状态 hash 已计算、所有该 tick 确定性输出已归并之后。检查点记录：

```text
completed_tick = T
resume_tick = T + 1
included_lsn = 该状态已经消费或纳入未来队列的最大 durable LSN
world_state_hash = tick T 的权威世界状态 hash，与 runtime/WAL 周期 hash 使用同一算法
checkpoint_content_hash = 按 provider ID 排序后，对 provider ID、schema 版本和 payload
                          计算的检查点内容 hash
```

两个 hash 不得混用：`world_state_hash` 用于确认恢复后的语义世界与捕获时一致，
`checkpoint_content_hash` 用于确认检查点覆盖的全部 provider 内容未被替换或漏校验。
manifest 与数据容器必须同时记录二者，加载时分别校验容器间一致性和重新计算的
内容 hash；发布阶段不得用内容 hash 覆盖运行时传入的世界 hash。

网络投影和异步落盘不属于状态 hash。检查点捕获必须返回不可变视图；世界继续执行后，后台线程只能访问不可变块或自有副本。禁止后台线程遍历仍在变化的 `World`。

## WAL 契约

### 记录什么

WAL 记录会影响确定性演化的外部输入和版本切换，不记录每个派生字段变化：

- Gateway 接纳的外部命令；
- IoT、文件导入和其他非确定性数据源的规范化输入；
- 管理员触发的规则、插件、schema 或配置版本切换；
- 随机流创建/重置等显式控制输入；
- 命令终态、周期状态 hash 和检查点标记等恢复/审计记录。

规则、AI 和 System 从上述输入确定性地产生的内部命令不重复写成外部输入 WAL。若某模块依赖墙钟、线程完成顺序、网络到达顺序或外部服务结果，该结果必须先规范化为 WAL 输入，之后才能进入运行时。

### LSN、顺序与耐久承诺

- `LogSequenceNumber` 是单世界、单分支内从 1 开始的 64 位单调序列，0 无效，溢出时拒绝继续写入；
- WAL writer 是 LSN 的唯一分配者；生产者不能自行指定 LSN；
- 同一批次按规范化 admission 顺序分配 LSN，线程调度和完成回调顺序不得改变记录顺序；
- 记录先写入当前 segment，经 `fdatasync/fsync` 成功后才完成 durable promise；
- 组提交允许合并多个 promise，但必须受命名配置的最大记录数、最大字节数和最大等待时间约束；
- `durable accepted` 表示对应输入和幂等键已经越过持久化边界，不等同于命令已经在目标 tick 应用；
- 磁盘满、权限错误、校验失败或同步失败时进入只读故障状态，拒绝新的 durable 输入，不允许降级为内存接纳；
- WAL 写入队列健康但积圧（达到配置上限）时，新的 durable admission 必须以稳定错误码显式拒绝，客户端可重试；不允许静默排队超过上限，也不允许因此降级为 relaxed。该拒绝与 M4 令牌桶限速是独立的两层：限速防滥用，队列上限防磁盘抖动拖垮内存；
- `relaxed` 耐久级别只允许基准和显式测试配置，响应必须使用不同状态，不能伪装成 durable accepted。

M5 需要扩展 M4 的命令接纳链路。当前 `(session_id, client_sequence)` 只能处理进程内重试，不能处理服务重启。外部 durable 命令必须增加客户端生成的 128 位 `request_id`，服务端以 `(principal_id, request_id)` 建立持久幂等索引：

```text
RPC request -> 鉴权/授权/边界校验 -> 规范化 DurableInput
            -> WAL group commit -> durable accepted + LSN
            -> 目标 tick CommandBuffer -> applied/rejected 终态
```

相同幂等键和相同内容返回既有结果；相同幂等键但内容不同必须稳定拒绝。终态回执在写入 outcome 记录后对外发布，重连后可按幂等键查询，防止“服务已经执行但响应在崩溃前丢失”导致重复操作。

### 分段文件与校验

WAL 使用版本化分段文件，不把整个历史追加到单一文件。每个 segment 包含固定格式头、连续记录和可选尾索引；每条记录使用长度前缀、格式版本、LSN、目标 tick、记录类型、payload 长度和 CRC32C。多字节整数固定为 little-endian，文件标识和版本是具名协议常量。

- 活跃 segment 不压缩；关闭并校验后的 segment 才允许用 Zstandard 归档；
- 启动时只允许修剪最后一个活跃 segment 尾部的不完整记录；
- 已关闭 segment、文件中部或 LSN 连续性出现损坏时必须停止恢复并报告位置，不能跳过坏记录继续运行；
- segment rotation、目录 manifest 和保留策略都使用原子临时文件、flush、rename、父目录 flush 的顺序提交；
- 删除旧 WAL 前必须存在已完成、重新打开验证成功且覆盖对应 LSN 的检查点，并满足保留策略。

FlatBuffers 负责 payload schema，不承担文件分帧、durability 或损坏恢复。CRC32C 用于损坏检测，不作为安全签名；需要防篡改部署时由后续存储适配器增加签名/不可变保留策略。

## 检查点与恢复

### 检查点格式

在 `schemas/persistence/` 建立独立 schema：

```text
wal_record.fbs
checkpoint_manifest.fbs
world_checkpoint.fbs
replay_manifest.fbs
branch_manifest.fbs
```

生成代码只进入构建目录。检查点 manifest 至少包含世界/分支 ID、格式版本、provider schema 列表、完成 tick、恢复 tick、included LSN、状态 hash、随机流、制品清单、数据块长度和校验和。

全量检查点按 provider 分块，块按稳定 provider ID 排序。相同状态、版本和配置必须产生逐字节一致的未压缩 payload；压缩容器的时间戳等非确定元数据不得进入内容 hash。

### 捕获与发布顺序

1. WAL writer 报告当前 durable LSN；
2. 在稳定 tick 边界冻结全部 provider，得到同一锚点的不可变状态视图；
3. 后台线程确定性编码、校验并可选压缩各数据块；
4. 数据写入临时文件并 flush；
5. manifest 写入临时文件并 flush；
6. 原子 rename 数据与 manifest，并 flush 目录；
7. 重新打开、校验长度、checksum、schema 和状态 hash 后标记检查点可恢复；
8. 只有发布成功后才允许按保留策略回收旧 segment 和旧检查点。

任何一步失败都保留上一份完整检查点；临时文件可在下次启动时清理，但不能被当成恢复候选。

### 检查点加载与 Copy-on-Write

M5-B PoC 已冻结为“磁盘 eager 恢复 + 内存持久化根 COW”：

- 检查点文件先完整读取，校验 manifest、长度和 CRC32C；压缩块用 Zstandard 解压后，按 provider 两阶段校验并 eager 物化。当前实现不是磁盘对象级惰性 mmap，也不以此名义承诺恢复内存占用；
- M5 构建下 `world_model` 使用 Immer 持久化 map。稳定 tick 边界的 `FrozenWorldSnapshot` 只复制持久化根，冻结为 O(1)，后续写入由 Immer 路径复制；M5 关闭时保留基础容器实现，不强迫早期阶段依赖 Immer；
- 推演分支共享同一 `FrozenWorldSnapshot`，各自只保存有序 overlay 和 tombstone；需要发布新检查点时再按稳定 WID 顺序物化；
- `mio` 用于 WAL segment 的只读映射扫描，不应据此把 checkpoint loader 描述成 mapped COW。

不得用 Linux `fork()` 作为 COW 实现。基线、overlay 和 tombstone 的合并顺序必须确定，迭代结果按稳定 ID 排序；冻结后继续修改原世界不得改变既有冻结根。磁盘对象级惰性映射若后续确有超大历史浏览需求，必须另立阶段设计按对象寻址的 checkpoint schema、压缩粒度和缓存淘汰，不能在 M5 文档中虚称已经具备。

### 恢复流程

1. 读取目录 manifest，选择最新且完整验证通过的检查点；
2. 校验构建兼容范围、schema registry、provider 版本、规则/插件/制品 hash 和固定步长；
3. 按依赖顺序恢复 provider，重建声明为派生的 ECS/空间索引；
4. 从 `included_lsn + 1` 连续扫描 WAL，将输入放回原始目标 tick；
5. 以无副作用模式推进到最后 durable 输入要求的 tick；
6. 在记录的 hash 点逐一比较，首个不一致即停止并生成差异诊断；
7. 恢复成功后建立新的 Gateway session、projection epoch 和连接状态，再开放接入。

未知权威 provider、缺失制品、无法完成的 schema upcast、固定步长不一致或 hash 分叉都必须拒绝进入可写服务。兼容迁移通过显式、逐版本 upcaster 完成，迁移后的检查点产生新世代，不原地覆盖旧文件。

## 回放与推演分支

### 可重放单元

一次可重放执行由以下内容共同标识：

```text
初始检查点引用
+ 连续 WAL 范围
+ 随机流状态
+ 固定步长
+ schema / 规则 / 插件 / 代码兼容标识
+ hash 算法版本
```

`gw-replay` 第一版提供：

- `inspect`：显示检查点、segment、LSN、tick、provider 和制品信息；
- `verify`：完整校验 manifest、schema、checksum、LSN 连续性和引用；
- `replay`：恢复到指定 LSN/tick，并输出周期 hash；
- `compare`：比较两次执行的 hash 序列和最终世界摘要；
- `bisect`：定位首个分叉 tick，并输出对象级 hash 差异；
- `fork`：从指定检查点/tick 创建分支 manifest 和独立 overlay WAL；
- `compact`：在校验与保留条件满足时生成新检查点并回收旧 segment。

所有命令默认只读；删除、compact 和发布迁移检查点需要显式输出目录，禁止隐式修改输入制品。

### 分支语义

- 基线检查点和已关闭 WAL segment 不可变，可被多个分支引用；
- 分支拥有独立 `BranchId`、WAL LSN 空间、输入幂等索引和输出目录；
- fork 不复制基线数据块，后续状态写入 COW overlay；
- 分支可替换 fork 点之后的输入和允许的规则制品，但 manifest 必须记录差异；
- 回放和分支默认禁用网络发送、数据库回写、通知和真实设备控制；
- 对外副作用只能由显式 side-effect sink 接收，测试默认使用记录型 sink；
- 合并两个分支不属于 M5。M5 只比较结果，不引入 CRDT、OT 或状态自动合并。

## 范围与实施批次

### M5-A：格式、WAL 与 durable admission

1. 建立 `geoworld_persistence`、持久化 schema 和 `vcpkg-m5` preset；
2. 冻结 LSN、record、segment、manifest、错误码和目录布局；
3. 实现单 writer、有界队列、组提交、rotation、checksum 和故障状态；
4. 扩展外部命令 `request_id` 与持久幂等索引；
5. Gateway durable admission 改为异步完成，不阻塞 world tick；
6. 完成断电尾记录、磁盘满、重复请求和 segment 损坏测试。

线协议演进约定：本批次对 M4 已冻结 schema 做**兼容演进而非开新版本**——`geoworld_control.proto` 的 SubmitCommand 请求增加可选 `request_id`（proto3 可选字段，旧客户端忽略）、回执与 GWCF/GWSF 回执枚举增加 `durable accepted` 状态值（枚举保持 `unspecified = 0` 在前，新增值追加在后，旧解码器按未知值安全处理）；控制面/数据面版本号不变，版本协商行为不变。演进落地时同步更新 `docs/M4.md` 的数据与接口契约小节。

本批次同时吸收 M4「2.0 阶段升级待办」中与本链路直接相关的两项（见 `docs/M4.md`）：命令提交链路重写时不得再丢弃 command submitter 返回值（入队失败必须回传为 admission 拒绝）；client_sequence/ingress_sequence 的回绕与 epoch 上限补齐明确拒绝语义。

### M5-B：完整检查点与恢复提供者

1. 建立 `CheckpointProvider` 注册、依赖排序和版本校验；
2. 为 world、clock、command buffer、FEL/事件、AI 意图、随机流和制品清单实现 provider；
3. 建立不可变捕获边界、后台编码、原子发布和保留策略；
4. 实现 eager restore，并为 mapped COW 基线完成真实负载 PoC；
5. 恢复后重建 ECS 和空间派生索引；
6. 完成完整、截断、未知 provider、schema 迁移和旧检查点回退测试。

### M5-C：恢复编排与确定性回放

1. `geoworldd` 启动接入恢复编排，恢复完成前不开放 Gateway；
2. 从检查点 LSN 连续重放，验证周期 hash 和最终 hash；
3. 记录并恢复命令终态与幂等结果；

## 三方依赖

M5 计划通过 vcpkg manifest 的 `m5` feature 引入：

| 依赖 | 用途 | 约束 |
|---|---|---|
| FlatBuffers | WAL payload、检查点和 manifest schema | 已有基础依赖；生成类型不泄漏公共 API |
| Google CRC32C | WAL record、数据块和 segment 损坏检测 | 不自研 checksum；不作为防篡改签名 |
| Zstandard | 已关闭 segment 和检查点块压缩 | 活跃 WAL 不压缩；压缩参数进入具名配置 |
| mio | WAL segment 跨平台只读 mmap 扫描 | 只在实现层使用；失败必须可诊断 |
| Boost.UUID | 解析/生成世界、分支和客户端 request UUID | 线格式固定为 128 位，不暴露 Boost 类型 |
| Immer | `World` 持久化根与路径复制 | M5 构建强制使用；类型不泄漏公共 API，M5 关闭保留基础容器路径 |

RocksDB/SQLite 的内部 WAL 不直接作为 GeoWorld 应用 WAL：它们不能替代 tick、输入类型、制品版本和确定性回放语义；未来可作为目录索引或存储适配器，但不得成为公共契约。

## 配置

配置必须使用具名字段并经过范围校验，至少包含：

- durable 根目录、世界 ID 和分支 ID；
- durability mode；
- group commit 最大等待、最大记录数和最大字节数；
- segment 最大字节数和最大存续时间；
- 检查点 tick 间隔、最小 durable LSN 增量和最大并发检查点数；
- WAL/checkpoint 保留数量、最小保留时长和磁盘水位；
- record、segment、provider block 和 checkpoint 大小上限；
- hash 记录间隔；
- 压缩启用、级别和最小块大小；
- 恢复模式、损坏尾部策略和只读恢复选项。

协议固定标识、版本和单位可以是命名常量；业务阈值、时间、大小和重试次数不得散落为固定值。

## 非目标

- 不实现 M6 的多进程复制、共识日志、leader election、authority handoff 或跨节点 checkpoint；
- 不让 PostgreSQL、PostGIS、TimescaleDB、TDengine、Redis 或对象存储参与 tick 提交；
- 不把 M4 客户端 keyframe/delta 当成恢复日志；
- 不实现字段级 event sourcing，也不承诺从任意字段历史自动还原业务事件；
- 不持久化 Gateway 连接、ticket、FID、ack 和发送队列；
- 不自动合并两个 what-if 分支；
- 不在 M5 建立历史可视化 GUI，先交付稳定 CLI 和机器可读报告；
- 不保证任意旧二进制都能重放新制品；兼容范围由显式 schema/upcaster 和制品版本决定；
- 不把 `fork()`、文件系统快照或容器 checkpoint 当作唯一跨平台实现；
- 不在缺少三方依赖时自行实现压缩、校验和、UUID 或通用 mmap 库。

## 风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| 当前模块缺少完整 snapshot/restore API | 恢复后未来行为分叉 | provider 注册强制完整性；有状态未注册即拒绝 durable 启动 |
| 检查点捕获深拷贝暂停 tick | p99 抖动、错过实时预算 | M5-B 真实负载比较不可变块/COW 方案；捕获暂停单独设门 |
| fsync 延迟波动 | durable admission 尾延迟升高 | 单 writer + 有界组提交；基准记录磁盘与文件系统；不在主 tick 等待 |
| 跨重启重复请求 | 命令重复执行 | `(principal_id, request_id)` 持久幂等索引和内容指纹 |
| schema/规则/代码升级 | 旧 WAL 无法确定性重放 | 制品内容寻址、兼容清单、逐版本 upcaster、缺失即拒绝 |
| WAL 尾部或 manifest 损坏 | 无法选择安全恢复点 | record CRC、原子发布、尾部与中部损坏采用不同 fail-closed 策略 |
| 回放触发真实副作用 | 重复通知、设备误控制 | 默认无副作用模式和显式 side-effect sink |
| COW overlay 长期增长 | 分支读放大和磁盘膨胀 | 可测量 compact；基线层数和 overlay 大小设上限 |
| 状态 hash 覆盖不完整 | 错误地判定回放一致 | hash 版本化并覆盖全部权威 provider，不只覆盖 `World` |

## 工程验收门

1. 在相同检查点、WAL、随机流和制品版本下，至少两次 Release 回放的每个记录 hash 点及最终权威 hash 完全一致；
2. durable accepted 后立即强制终止进程，重启后对应命令必须执行且只执行一次；响应丢失后的同幂等键重试返回既有结果；
3. 在 append、sync、segment rotation、checkpoint data、manifest rename 和保留回收关键窗口注入崩溃，恢复结果只能是上一承诺点或当前承诺点，不能出现部分状态；
4. 最后活跃 segment 的截断尾记录可按策略修复；已关闭 segment 或文件中部损坏必须稳定拒绝恢复并报告 segment、offset 和期望 LSN；
5. 完整检查点恢复后，在无新输入情况下的权威 hash 与捕获时一致；继续重放后与未崩溃基线逐 tick 一致；
6. 未注册有状态 provider、未知权威 schema、缺失规则/插件制品和不连续 LSN 均禁止进入可写服务；
7. eager 恢复世界与其 `FrozenWorldSnapshot`/overlay 物化结果 hash 一致；创建分支不复制基线文件，冻结后原世界修改不污染分支，分支外部副作用计数为 0；
8. 10 万实体、20 Hz 标准负载下，WAL 入队不得阻塞 world tick；检查点捕获导致的 tick 额外暂停 p99 不超过 10 ms，后台检查点期间 tick p99 相对无检查点基线恶化不超过 20%；该门与门 10 一样以 M5-B 首轮自有基准数据复核，捕获设计未冻结前不允许无数据放宽，也不允许靠删减检查点内容达标；
9. 本机 NVMe、Release、durable group commit 场景下记录 fsync/admission p50/p95/p99 和吞吐；阶段收口前根据真实磁盘数据冻结容量门，不用 tmpfs 或 page cache 数字代替耐久结论；
10. 10 万实体完整恢复到可继续推进状态不超过 30 秒，恢复期间 checksum、schema 和 hash 校验全部开启；该门在 M5-B 首轮自有基准后可依据产品 RTO 更新，但不得无数据放宽；
11. WAL 与检查点保留长稳态运行不少于 10 分钟，目录大小进入稳定区间，无未引用临时文件、断链 manifest 或持续 RSS 增长；
12. CMake 配置、Debug/Release 构建、CTest、ASan/UBSan 恢复生命周期测试和 M5 自有基准全部通过，结果与环境记录在本文。

- **第 1/3 条 provider 框架**（`libs/persistence/include/geoworld/persistence/checkpoint.hpp` + `src/checkpoint.cpp`/`checkpoint_codec.cpp`）：`CheckpointProvider` 接口 freeze（tick 线程拷贝冻结）/encode（后台确定性编码，两者经类型擦除的 `FrozenProviderState` 分离）/restore/restore_dependencies；`CheckpointRegistry` 按稳定 ID 排序捕获、拓扑排序恢复、依赖环与未知依赖拒绝、`validate_completeness` 完整性闸门；`CheckpointCoordinator::capture/publish` 八步发布（冻结 → 后台编码 → 数据块原子写 → manifest 原子提交 → 重开校验长度/CRC/锚点/schema 一致 → 保留回收）；检查点命名 `ckpt-<tick:020d>.gwck/.gwckm`，manifest 是提交点；保留策略 `keep_last_checkpoints` 回收旧检查点对，并回收被 included_lsn 覆盖的已关闭 WAL 段（活跃段与无后继末段保守保留）。
- **第 4 条 核心 provider**（`src/provider_world.cpp`）：world payload v1 全小端逐字段编码（对象按 id 序、属性包按 `std::map` 键序、关系/能力按插入序，同一历史逐字节确定），lifecycle 越界拒绝、解码严格边界与末尾检查；clock payload 为 next_tick + dt_microseconds，固定步长不一致以 GWP001 拒绝恢复。`TickClock` 追加 `restore_tick`。
- **第 6 条 eager restore**（`recovery.hpp` + `src/recovery.cpp`）：`CheckpointLoader` 扫描目录排除 tmp/截断/CRC 不符候选，`load` 重校验数据块 CRC，`restore_into` 按拓扑序恢复——已注册 provider 缺块 GWP020、schema 版本不符 GWP018（无 upcaster 即拒绝）、检查点含未注册块 GWP017。
- **测试**：`tests/unit/checkpoint_test.cpp`（`geoworld.checkpoint`，9 用例：注册排序/依赖拓扑/完整性闸门、world roundtrip hash 与单调计数器接续、clock roundtrip 与 dt 守卫、双目录逐字节确定性、捕获后变异隔离、CRC 损坏与截断拒绝、未知 provider/缺块/版本不符三拒绝、保留回收只删已发布、WAL 段裁剪边界）；`tests/integration/m5_checkpoint_test.cpp`（`geoworld.m5_checkpoint`：WorldRuntime 锚点捕获 → 发布 → 全新运行时 eager 恢复后 hash/tick 一致且无新输入推进 hash 稳定，durable 启动完整性闸门）。
- **验证**：`build/agent-m5c`（Debug，`VCPKG_MANIFEST_FEATURES="m4;m5"`，`GW_BUILD_M4/M5=ON`）全量 CTest 25/25 通过，构建零警告。

### M5-B 收口：完整 provider、不可变捕获与恢复（2026-08-14 完成）

- **完整 provider 集合**：补齐 `command_buffer`、`event_bus`、`ai_intents`、`random_streams`、`artifacts`、`ecs_active_set`；命令排序序列、未来事件、待处理意图、命名随机流位置、制品 hash 和 ECS 活跃 WID 均进入检查点。恢复采用 validate-all/commit-all，两阶段校验失败不留下半恢复运行时。
- **水位真相源**：`included_lsn` 只由 command buffer 冻结状态提供，包含合法的 0 水位；已经写入 WAL、尚未进入命令缓冲的 admission 不会被检查点错误吞掉。发布端不再用 writer 当前 LSN 冒充“已纳入未来状态”的水位。
- **Immer 决策**：`m5` feature 引入 Immer 0.9.1；M5 下 `World` 的冻结根为 O(1)，后续对象写入路径复制。冻结后修改原世界、分支之间修改均有隔离断言；非 M5 构建仍走基础容器路径。
- **编码与发布**：provider 块按 ID 稳定排序，checkpoint 支持具名 Zstandard 级别与压缩阈值；数据/manifest 原子发布后重新打开校验，临时文件不参与恢复。schema 版本不同时只允许 provider 显式逐版本 upcast，已覆盖 v0→v1 正向迁移与无迁移拒绝。
- **恢复派生状态**：ECS provider 在 world 之后恢复活跃 WID，重新建立 RuntimeId 映射；缺失对象、未知 provider、依赖环、固定步长或制品不兼容均 fail-closed。
- **WAL 回收续写**：扫描结果暴露 `first_lsn/next_lsn`；有检查点锚定时允许从首个保留 segment 继续，writer 通过 `recovery_floor_lsn` 从安全位置续写，空活跃段按文件名恢复起始 LSN。无检查点锚定却缺少早期 segment 时仍以 LSN 不连续拒绝。

### M5-C：启动恢复与确定性回放（2026-08-14 完成）

- `geoworldd` 在启动 Gateway 前构建恢复计划，加载最新完整 checkpoint，按 LSN 连续回放后续外部输入并校验记录的状态 hash；恢复失败不会开放可写服务。
- 恢复时以真实 `ApplyReport` 重建终态：缺失的 `command_outcome` 在 Gateway 开放前补写并同步，随后重建 `(principal_id, request_id)` 幂等索引，避免“命令已执行、终态 WAL 未写”导致重复执行。
- `tests/integration/m5_recovery_test.cpp` 包含真实子进程故障：子进程收到 durable accepted 后由父进程发送 `SIGKILL`；重启扫描仍读到输入，恢复执行一次，第二次恢复得到相同 hash，最终 outcome 写回后幂等状态为 applied。
- `gw-replay` 已提供 `inspect`、`verify`、`replay`、`compare`、`bisect`、`fork`、`compact`。回放严格校验 checkpoint/WAL/hash；compare 输出对象差异，compact 只写显式输出目录。

### M5-D：共享基线推演分支（2026-08-14 完成）

- 分支 manifest 记录 parent/child、fork tick/LSN、父 checkpoint 引用和独立 overlay WAL；`fork` 可选择指定 checkpoint tick，子目录不复制 checkpoint 数据文件。
- 子分支恢复会验证并加载 manifest 指定的父 checkpoint，再从 `fork_lsn + 1` 扫描独立 WAL；writer 使用同一 recovery floor 安全续写。
- `WorldOverlay` 在 Immer 冻结根上维护有序变更与 tombstone，物化和对象差异比较均按稳定 WID；默认 `DisabledSideEffectSink` 拒绝外部副作用。
- 父分支检查点回收会扫描同世界的兄弟分支引用，被任何子分支钉住的 checkpoint 不删除。测试覆盖指定 tick 分叉、实际恢复、继续写入、兄弟引用保留和分支隔离。
