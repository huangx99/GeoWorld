# M4：接入层

> 状态：规划已冻结，暂停实施 | 计划基线日期：2026-08-12

## 目标

建立客户端观察和操作权威世界的稳定接入层，交付“权威世界 → 客户端投影 → 版本化协议 → Gateway → 参考客户端”的完整闭环。M4 完成后，浏览器、Qt 或其他客户端可以通过相同的控制面语义和数据面制品观察世界，不需要了解 flecs、世界内部容器或仿真线程。

M4 只建立通用接入框架，不包含行业界面和领域协议。开始实施前必须把本文状态改为“实施中”；本文处于“暂停实施”时，不应创建 M4 代码或引入 M4 三方依赖。

## 产品与工程价值

- 客户端只接收与自身订阅相关的实体，避免全世界广播；
- 用 keyframe、delta、ack 和重新同步处理慢客户端、断线和基线过期；
- 用控制面/数据面分离避免把高频世界状态塞进 gRPC 请求响应链路；
- 将网络连接、鉴权和协议适配隔离在 Gateway，世界运行时不依赖客户端技术；
- 客户端提交意图而不是直接写状态，所有成功修改仍通过 `simulation::CommandBuffer`；
- 建立可复现的 R4 扇出基准，为容量规划提供自有数据。

## 架构边界

### 模块职责

| 模块 | 职责 | 明确禁止 |
|---|---|---|
| `projection` | 在稳定 tick 边界生成客户端视图；维护共享投影历史、订阅可见集、FID 映射、基线和 delta | 不开放 flecs 类型；不持有网络连接；不修改世界 |
| `protocol` | 定义 Protobuf 控制面和 FlatBuffers 数据面 schema；在内部 DTO 与线格式之间转换和校验 | 不执行业务命令；不维护连接；生成类型不泄漏到其他模块公共 API |
| `gateway` | 会话、鉴权、授权、限速、虚拟连接、ack、背压、重连和传输适配 | 不成为世界真相源；不绕过命令缓冲；不包含领域规则 |
| `apps/geoworldd` | 组合 `WorldRuntime`、投影、协议和 Gateway，管理启动与关闭 | 不把协议逻辑重新写进应用入口 |
| `tools/gw-stream-client` | 无界面的参考客户端，验证 keyframe/delta 重建、ack、重连和插值输入 | 不发展为正式三维客户端或领域 UI |

依赖方向冻结为：

```text
foundation + schema + world_model + spatial -> projection
foundation + schema                         -> protocol
projection + protocol + simulation          -> gateway
world_runtime + projection + protocol + gateway -> geoworldd
```

- `world_model`、`ecs_runtime`、`simulation` 和 `spatial` 不得反向依赖 M4 模块；
- `gateway` 只能通过显式运行时命令入口提交修改，不能获得可写 `world::World&`；
- IO 线程不能持有世界对象、ECS entity、容器迭代器或原始指针；跨线程只传递不可变投影和自有字节缓冲；
- 网络时序、墙钟、线程调度和日志不得进入世界状态 hash；
- M4 不复用 `ecs::RuntimeSnapshot` 作为客户端协议。它只包含运行时 ID 投影所需的少量字段，语义和版本生命周期均不同；
- `schemas/data/runtime_snapshot.fbs` 保持 ECS 快照用途。M4 必须建立独立的流式数据 schema 和文件标识。

### 稳定投影边界

当前 `WorldRuntime` 已有 `TickPhase::projection`，但通用 phase callback 仍接收可写 `world::World&`。M4-A 必须增加专用的只读投影观察入口，使投影发生在 Track A/B/C 完成、当 tick 世界稳定、`clock.advance()` 之前：

```text
apply 到期命令 -> Track A -> Track B -> Track C -> state hash
              -> 只读 projection observer -> clock.advance
```

投影观察入口至少接收：

- `const world::World&`；
- 当前 `tick`；
- 当前状态 hash；
- 只读空间查询能力。

投影不能依赖可写 phase callback 的注册顺序，也不能把编码、网络发送放在世界线程中。世界线程只发布不可变的规范化投影，编码和扇出在有界工作队列中完成。

## 范围与实施批次

### M4-A：客户端投影内核

1. 建立 `geoworld_projection` CMake target 和 `include/geoworld/projection/` 公共 API；
2. 从 `world::WorldObject` 生成版本化、确定性排序的 `ProjectedEntity`；
3. 通过 `ProjectionPolicy` 选择允许向客户端暴露的字段，不默认泄露全部属性；
4. 基于 `SpatialQuery` 计算连接 AOI 候选，再叠加读权限、更新频率和优先级；
5. 维护每个虚拟连接的 WID↔FID 映射、可见集、发送历史和已确认基线；
6. 生成 keyframe 及 `enter/update/leave` delta；
7. 增加只读 projection observer，保证投影不修改权威世界；
8. 完成快照、delta、基线过期、确定性和内存上限测试。

M4-A 不依赖 gRPC 或实际 socket，应能独立进行单元测试和基准。

### M4-B：版本化协议

1. 在 `schemas/control/` 新增 `geoworld_control.proto`；
2. 在 `schemas/data/` 新增服务端流帧和客户端流控制 FlatBuffers schema；
3. 建立 `geoworld_protocol`，封装生成类型、verifier、编码和解码；
4. 生成代码只进入 `build/generated/m4/`；
5. 固定协议协商、错误码、大小上限和兼容性策略；
6. 建立无网络参与的逐字节确定性编码和恶意输入拒绝测试；
7. 建立参考客户端的 replica accumulator 和插值输入缓冲。

### M4-C：Gateway 与第一条真实链路

1. 建立 `geoworld_gateway` 和 `vcpkg-m4` preset；
2. 用 gRPC/Protobuf 实现低频控制面；
3. 用 Boost.Asio + Boost.Beast 实现第一条 WebSocket 二进制数据链路；
4. 非 loopback 部署使用 OpenSSL TLS，明文只允许显式测试配置；
5. 实现会话、短期 stream ticket、虚拟连接、鉴权/授权 provider、限速和审计；
6. 实现 ack、重新同步、断线重连、状态队列与可靠队列的独立背压；
7. 外部命令经乐观并发校验后进入命令缓冲，并产生终态回执；
8. `apps/geoworldd` 成为可启动的组合根；
9. `gw-stream-client` 完成 loopback 端到端闭环。

选择 WebSocket 作为第一条链路不是推翻 ADR9。它先兑现必须长期维护的浏览器降级路径，并验证投影、协议和背压；传输接口必须允许后续增加 WebTransport/QUIC，而无需修改投影或世界运行时。

### M4-D：恢复、慢客户端与安全测试

1. ack 乱序、重复、过旧和未知 snapshot 的处理；
2. 发送历史淘汰后自动 keyframe；
3. 传输重连后建立新 stream epoch，重置 FID 并发送 keyframe；
4. 慢客户端状态帧合并、可靠消息保护和有界断开；
5. 畸形 Protobuf/FlatBuffers、超大帧、未授权命令和重放 ticket 测试；
6. TLS loopback 集成测试；
7. 地址、token 和 payload 日志脱敏；
8. ASan/UBSan 可用配置下的连接生命周期测试。

### M4-E：R4 扇出基准与阶段收口

1. 在 `benchmarks/` 增加可配置的权威世界、AOI 和虚拟连接负载；
2. 分开测量投影采集、AOI、delta 构建、FlatBuffers 编码和 Gateway 入队；
3. 记录吞吐、p50/p95/p99、带宽、队列、RSS、重同步和断开原因；
4. 加入慢客户端隔离场景；
5. 把机器、编译器、Release 配置、参数和结果记录在本文；
6. 满足本文验收标准后才将 M4 标为完成。

## 非目标

- 不实现 M5 的 WAL、持久化快照、操作日志压缩或历史回放；
- 不实现 M6 的多进程复制、authority handoff、ghost 或动态分片；
- 不实现账户数据库、密码系统、OAuth/OIDC 服务端或证书自动签发；
- 不实现正式 Web/Qt/三维客户端，只交付无界面参考客户端；
- 不实现客户端预测的具体移动/物理模型，只传递预测和和解需要的序号、tick 与权威状态；
- 不引入 CRDT、OT 或多人场景编辑器；
- 不实现领域命令、领域字段白名单或行业权限模型；
- 不做字段级二进制 patch。M4 delta 中的 `update` 携带该实体完整的最新投影，先保证正确性和可演进性；
- 不自研 HTTP、WebSocket、TLS、QUIC、Protobuf 或 FlatBuffers 实现；
- WebTransport/原生 QUIC 不是 M4 核心退出条件。开始对应适配前必须更新本文并冻结成熟三方库，下载失败不能改为自研协议栈。

## 数据与接口契约

### 标识与时序

| 字段 | 类型和语义 |
|---|---|
| `WorldId` | 权威 64 位 WID，跨连接稳定，0 无效 |
| `FeatureId` | 连接 stream epoch 内有效的 32 位 FID，0 无效；epoch 内不复用 |
| `session_id` | 控制面会话 ID，不作为世界对象 ID |
| `stream_epoch` | 每次数据链路建立时递增；重连必须建立新 epoch |
| `snapshot_id` | 64 位全局单调递增投影代次 ID；每次 projection phase 分配一次并供全部连接引用，0 表示“无基线” |
| `baseline_snapshot_id` | 生成 delta 所依据的、客户端已经确认的快照 ID |
| `stream_sequence` | 每个 stream epoch 独立递增的服务端帧序号 |
| `client_sequence` | 每个 session 独立递增的客户端命令序号，用于去重与回执关联 |
| `tick` | 该投影对应的权威逻辑帧；不使用墙钟代替 |
| `simulation_time_us` | 从固定 tick 配置计算出的仿真时间 |

FID 由连接投影状态管理。新 epoch 按 WID 升序分配 FID；发送 `enter` 前必须先建立映射。为防止延迟帧把旧实体误认成新实体，M4 不在同一 epoch 内回收 FID。达到配置上限时发送明确错误并重建 epoch，不能静默环绕。

当前 `spatial::AoiManager` 以观察者 WID 为键；虚拟连接不一定对应世界实体。M4 不得制造假的 WID 充当连接 ID。连接订阅视图应以独立强类型 `ConnectionId` 管理，复用 `SpatialQuery` 查询候选；“跟随某个世界实体”是订阅参数，不是连接身份。

`snapshot_id` 不等于 `tick`：一个 tick 最多产生一个投影代次，但二者分别编码，以便未来支持跳过未变化 tick 或按配置降频。ID 递增溢出必须使服务拒绝继续启动/运行，禁止归零复用。`stream_sequence` 和 `client_sequence` 同样禁止在有效 epoch/session 内环绕。

### 投影实体

`ProjectedEntity` 的第一版至少包含：

- WID、FID 和对象版本；
- ECEF double 位置；
- semantic type、geometry reference 和 lifecycle；
- 经 `ProjectionPolicy` 允许的 properties、state、relations 和 capabilities；
- 可选的投影元数据：更新频率档位、优先级和可见性标签。

`schema::Value` 映射为明确的 FlatBuffers union，覆盖 `int64`、`double`、`bool` 和 UTF-8 string。map 按 key 排序；relations 按 `(type, target WID)` 排序；capabilities 去重后排序。相同世界状态、策略和订阅必须得到逐字节相同的规范化投影。

对象 `version` 用于客户端乐观并发，但不能作为唯一变化检测依据：目前并非所有未来组件变化都保证通过 `World::set_property()`。M4-A 必须比较规范化投影或其稳定 hash，确保位置、关系、state 和策略变化都能产生 `update`。

### keyframe 与 delta

服务端帧分为：

- `Keyframe`：当前连接完整可见集及完整 FID 映射，`baseline_snapshot_id = 0`；
- `Delta`：相对于一个已确认且仍保留的基线，包含 `enter`、`update`、`leave`；
- `ReliableEvent`：不可被状态帧合并丢弃的事件、命令终态回执和协议错误；
- `Heartbeat`：连接活性及最新服务器 tick，不参与 replica 状态。

规则冻结如下：

1. `enter` 携带完整投影实体；
2. `update` 携带完整最新投影实体，不做字段 patch；
3. `leave` 携带 FID、WID 和离开原因；离开原因只用于诊断，不能改变客户端删除语义；
4. delta 内按 `leave(FID)`、`enter(WID)`、`update(FID)` 各自升序输出；
5. ack 只接受当前 stream epoch 内已经发送的 snapshot；重复或较旧 ack 幂等忽略，未来或未知 ack 触发协议错误；
6. ack 基线已被历史环淘汰、策略改变、权限改变或 FID 空间耗尽时，下一状态帧必须是 keyframe；
7. 重连建立新 epoch，旧 epoch 的帧和 ack 一律拒绝；第一帧必须是 keyframe；
8. 客户端应用 keyframe/delta 后的规范化 replica hash 必须与服务端该连接的投影视图 hash 一致。

历史和基线的内存模型冻结为：

- 全局只保存按 snapshot 组织的共享规范化变化记录，不为每个连接复制一份 10 万实体世界；
- 每连接只保存当前已确认 replica 的可见 WID/FID、实体投影 hash、未确认发送记录和策略版本；
- 未确认记录保存足以把已确认 replica 推进到某个已发送 snapshot 的操作或不可变缓冲引用，受帧数和字节双重上限约束；
- ack 到达后按顺序推进已确认 replica 并释放更旧记录；
- 无法从当前已确认基线安全生成 delta 时发送 keyframe，不能猜测客户端状态；
- 不允许实现成“每连接 × 历史帧数 × 完整可见实体”的全量矩阵。R4 内存基准必须单独报告共享历史、连接状态和发送队列的字节数。

### 订阅、相关性和频率

订阅请求使用 ENU AABB 或“跟随 WID + 半径/层级”描述兴趣区域。Gateway 校验范围和权限后交给投影层。处理顺序固定为：

```text
SpatialQuery 候选 -> 读权限/相关性 -> ProjectionPolicy 字段裁剪
                  -> 频率到期判定 -> 带宽不足时优先级调度
```

更新频率至少包含：

- `on_change`：静态或缓慢对象，仅在进入、离开或投影变化时发送；
- `slow`：低频状态刷新；
- `fast`：移动实体的常规数据频率。

频率和优先级来自策略或配置，不能根据 semantic type 在 Gateway 中写死行业规则。低优先级对象因配额延迟时，等待时间必须进入优先级计算，避免永久饥饿。

### 控制面 RPC

Protobuf package 使用 `geoworld.control.v1`。第一版至少提供：

| RPC | 用途 |
|---|---|
| `OpenSession` | 验证 credential，协商协议版本，返回 session、短期 stream ticket 和数据端点 |
| `CloseSession` | 幂等关闭会话并释放所有权和订阅 |
| `UpdateSubscription` | 设置/替换 AOI、字段策略和频率档位 |
| `AcquireOwnership` | 申请 WID 的属性集合写权，租约以目标 simulation tick 表达 |
| `ReleaseOwnership` | 幂等释放属性写权 |
| `SubmitCommand` | 提交客户端意图，返回接收或拒绝结果；最终执行结果通过可靠回执返回 |
| `RequestKeyframe` | 丢失基线或客户端检测到 replica 不一致时请求重新同步 |
| `GetServerInfo` | 返回构建版本、协议范围、当前 tick 和可用能力，不返回敏感配置 |

gRPC 不承载持续高频世界状态。浏览器 gRPC-Web 代理、REST 和管理后台均不属于 M4 核心范围。

### 线协议版本与错误码

M4 v1 冻结以下命名和标识：

- Protobuf package：`geoworld.control.v1`；
- 服务端数据帧 FlatBuffers identifier：`GWSF`；
- 客户端数据控制帧 FlatBuffers identifier：`GWCF`；
- `control_api_version = 1`、`data_schema_version = 1`、`projection_schema_version = 1`；
- WebSocket subprotocol：`geoworld.stream.v1`。

`OpenSession` 请求提供客户端支持的控制面和数据面版本范围，服务端选择双方共同的最高版本；无交集时拒绝会话。stream ticket 绑定已协商版本，WebSocket 握手必须携带匹配的 subprotocol。FlatBuffers 帧同时校验 identifier、schema version、epoch、长度和 verifier。v1 内 FlatBuffers 只能在末尾追加可选字段，不能改变已有字段含义；破坏性变化使用新 identifier/subprotocol 和新的 Protobuf package。

稳定错误码第一批如下，后续只能追加，不能复用或改变语义：

| 错误码 | 含义 |
|---|---|
| `GWG001` | 协议或 schema 版本不兼容 |
| `GWG002` | 认证失败 |
| `GWG003` | 权限或属性所有权不足 |
| `GWG004` | 请求或命令超过速率限制 |
| `GWG005` | 请求字段、枚举或状态转换无效 |
| `GWG006` | 消息、字段或队列超过配置上限 |
| `GWG101` | stream ticket 无效、过期或已使用 |
| `GWG102` | stream epoch 不匹配 |
| `GWG103` | ack 指向未来、未知或未发送的 snapshot |
| `GWG104` | delta 基线不可用，需要 keyframe |
| `GWG105` | 慢客户端超过可靠队列或超时上限 |
| `GWG201` | 对象版本冲突 |
| `GWG202` | 目标对象或属性不存在 |
| `GWG203` | 目标 tick 超出允许窗口 |
| `GWG204` | 命令 operation 不受支持 |

重复旧 ack 是幂等成功，不返回 `GWG103`；`RequestKeyframe` 也是幂等操作。命令重复提交返回 `duplicate` 回执及原结果，不作为协议错误。

### 命令接入与并发控制

外部命令使用传输无关的内部 DTO，至少包含：

```text
session / principal / client_sequence / target_tick
target WID / operation / parameters / expected_object_version
```

命令处理分为两步：

1. Gateway admission：协议、身份、权限、所有权、速率、参数大小、允许的 operation 和目标 tick 窗口；
2. 仿真相位提交：在真正 apply 时检查 `expected_object_version`，通过后写入 `CommandBuffer`，产生 `applied` 或 `rejected` 终态。

仅在 admission 成功不能向客户端宣称世界已经修改。回执状态至少区分 `accepted`、`applied`、`rejected` 和 `duplicate`。同一 `(session_id, client_sequence)` 重试必须返回缓存结果，不得重复入队。

M4 允许为 `simulation`/`WorldRuntime` 增加传输无关的命令 metadata、版本前置条件和逐命令结果接口，但不能把 Protobuf、FlatBuffers、连接对象或 principal 类型放入 `simulation` 公共 API。

外部命令不能指定任意历史 tick。默认由 Gateway 在 admission 时指定 `current_tick + command_lead_ticks`；客户端给出的期望 tick 仅是提示，必须落在 `[current_tick + 1, current_tick + max_command_lead_ticks]`。Gateway 为 admission 成功的命令分配单调 `ingress_sequence`，运行时 input phase 按 `(target_tick, ingress_sequence)` 入命令缓冲。该序列属于权威输入，M5 记录回放时必须一并记录；不能用 IO callback 的执行线程顺序直接决定 apply 顺序。

默认观察者只读。`SetProperty` 必须拥有对应属性写权；`CreateObject` 和 `DestroyObject` 只允许管理权限。M4 的 `AuthenticationProvider` 与 `AuthorizationPolicy` 是可替换接口：测试提供者可以使用固定 fixture，生产提供者由部署方实现。M4 不自建用户数据库。

## 协议与三方库决策

| 能力 | 冻结选择 | 接入纪律 |
|---|---|---|
| 控制面 | gRPC + Protobuf | vcpkg manifest；只用于低频 RPC |
| 数据序列化 | FlatBuffers | schema 在 `schemas/data/`；所有输入先 verifier |
| 第一条数据传输 | Boost.Asio + Boost.Beast WebSocket | 二进制帧；传输实现隐藏在 adapter 后 |
| TLS | OpenSSL | 非 loopback 默认必须 TLS；测试证书不提交私钥 |
| WebTransport/QUIC | 暂缓具体库选择 | 后续 PoC 更新本文，不能自研替代成熟库 |

计划开始 M4 时，`vcpkg.json` 的 `m4` feature 应至少包含 gRPC、Protobuf、Boost.Asio、Boost.Beast 和 OpenSSL；FlatBuffers 已是基础依赖。新增 `vcpkg-m4` preset，并以 `GW_BUILD_M4` 显式控制网络目标。默认无 M4 依赖的构建必须继续通过。

所有三方类型都留在 adapter 或 `protocol` 实现中。`projection` 和 `gateway` 公共接口使用 GeoWorld 自有强类型、`std::span` 和自有字节缓冲，不暴露 `grpc::*`、`flatbuffers::*`、Beast stream 或 OpenSSL handle。

## 配置基线

以下是第一版具名配置的默认值，不是允许散落在代码中的常量。实现时集中到 `ProjectionConfig`、`GatewayConfig`、`ProtocolLimits` 和基准参数，并支持测试覆盖：

| 配置项 | 默认值 | 说明 |
|---|---:|---|
| `data_frequency_hz` | 20 Hz | fast 状态帧频率 |
| `slow_frequency_hz` | 2 Hz | slow 档位刷新频率 |
| `keyframe_interval` | 5 s | 正常连接的周期 keyframe |
| `interpolation_delay` | 100 ms | 参考客户端渲染采样延迟 |
| `snapshot_history_frames` | 256 | 共享规范化变化历史上限；不是每连接全量快照数 |
| `max_unacked_frames` | 256 | 每连接未确认 snapshot ID/操作记录上限 |
| `max_unacked_bytes` | 16 MiB | 每连接未确认不可变缓冲/操作记录上限 |
| `max_state_queue_bytes` | 4 MiB | 可合并状态队列上限 |
| `max_reliable_queue_bytes` | 1 MiB | 不可丢可靠消息队列上限 |
| `max_frame_bytes` | 8 MiB | 单个数据帧硬上限 |
| `ack_timeout` | 10 s | 超时后强制重新同步或断开 |
| `stream_ticket_ttl` | 30 s | 一次性数据链路 ticket 有效期 |
| `command_rate_per_session` | 100/s | 默认命令令牌桶补充速率 |
| `command_lead_ticks` | 1 tick | Gateway 默认安排到下一逻辑帧 |
| `max_command_lead_ticks` | 5 ticks | 客户端允许请求的最远未来 tick |
| `gateway_io_threads` | 2 | IO executor 工作线程数 |
| `encoding_workers` | 4 | 投影编码工作数；基准必须显式记录 |

配置非法时启动必须失败并输出明确诊断，不能静默改回固定值。生产值可以由部署配置覆盖，但覆盖不得改变协议语义。

## 背压与线程模型

- 世界线程发布不可变投影，不等待 socket；
- 每连接分离 state queue 与 reliable queue；
- state queue 达到上限时可以丢弃尚未发送的中间状态，合并到最新视图或安排 keyframe；不能生成引用已丢弃基线的 delta；
- reliable queue 不丢命令终态回执和协议错误。达到上限时以明确原因断开慢客户端；
- 慢客户端不能阻塞世界 tick、其他连接或 Gateway accept loop；
- 所有队列必须有字节和条目双重上限；
- 连接关闭、session 关闭和进程退出均必须取消异步操作并释放队列，不留下访问已卸载对象的 callback；
- Gateway 线程数、编码工作数和队列容量均由配置提供，不以 CPU 数量推导不可测试的隐式行为。

## 安全与可观测性

### 安全基线

- 非 loopback 数据面和控制面默认 TLS；
- stream ticket 一次性、短期有效并绑定 session 与协议版本；
- 所有 Protobuf/FlatBuffers 输入先做深度、长度、枚举和 verifier 校验；
- operation 使用白名单枚举，不接受反射式任意函数名；
- 字符串、属性数量、关系数量、AOI 范围和帧大小均有配置上限；
- 错误响应不包含文件路径、堆栈、token、证书或内部地址；
- token 和完整 payload 不进入日志；
- 未授权、超限、协议不兼容和基线错误使用稳定错误码。

### 必备指标

- 投影采集和规范化耗时、实体数、投影字节；
- AOI 候选数、可见数、enter/update/leave 数；
- keyframe/delta 数量、编码耗时和字节；
- 活跃 session/connection、重连、重新同步和断开原因；
- 每连接 ack lag、state/reliable queue 字节和合并次数；
- 控制面 RPC p50/p95/p99、命令 accepted/applied/rejected/duplicate；
- Gateway 总扇出字节、健康连接延迟和慢客户端隔离结果。

高频指标使用聚合或有界采样，不能为每个实体写日志。

## R4 可复现基准

### 标准负载

`benchmarks/m4_gateway_benchmark.cpp` 的标准 Release 负载冻结为：

- 权威世界实体：100,000；
- 虚拟连接：256；
- 每连接平均可见实体：2,000，AOI 分布必须有重叠，不能让每连接拥有独立小世界；
- fast 发射频率：20 Hz；
- 每次发射改变可见实体的 10%；
- keyframe 周期：5 s；
- 预热：30 s；正式采样：10 min；
- schema 至少包含 WID、FID、version、ECEF、semantic type、geometry reference、两个数值属性和一个字符串状态；
- 使用真实 FlatBuffers 编码和真实 Gateway 有界队列；不能用计数器替代制品构建；
- 基准默认使用内存传输 sink 隔离公网和 TLS 抖动，另设 loopback WebSocket/TLS 集成负载测传输开销。

另设慢客户端负载：5% 连接停止消费 30 s，其余连接正常 ack。

### 工程验收门

这些数字是 M4 第一版工程门槛，不是对客户的 SLA。修改门槛必须先更新本文并说明机器与产品约束：

1. 标准负载持续达到 20 Hz，无 verifier 错误、崩溃或健康连接断开；
2. 从投影边界到所有健康连接完成 Gateway 入队的 p99 不超过 50 ms；
3. 参考客户端在每次 keyframe 后以及连续 delta 应用后，投影视图 hash 与服务端一致；
4. 每连接平均数据带宽不超过 2 MiB/s；超过时必须提供字段/频率/编码归因，不能直接删除协议能力；
5. 预热后健康负载 RSS 增长不超过 5%，所有连接队列始终受配置上限约束；
6. 慢客户端场景中，健康连接 p99 相对标准负载恶化不超过 20%；慢连接按规则合并、重新同步或断开；
7. ack 基线过期、帧丢失、重复帧和重连测试均能通过 keyframe 恢复，恢复后 hash 一致；
8. loopback 下控制面 `SubmitCommand` admission p99 不超过 50 ms，终态回执不得丢失或重复执行；
9. 基准输出机器 CPU、内存、OS、编译器、构建类型、依赖版本、随机种子和全部负载参数。

CPU 占用和绝对 RSS 只记录，不在未知部署硬件前伪造通用容量目标。基准结果必须保存在本文的“当前进度/容量记录”，不能只保留一次终端输出。

## 风险和预定处理

| 风险 | 处理方式 |
|---|---|
| 全量 `World::snapshot()` 复制 10 万对象过慢 | M4-A 先测量；投影接口允许后续增量 change feed，但不能绕过稳定相位读取可变容器 |
| `WorldObject::version` 未覆盖所有变化 | 变化检测使用规范化投影/hash，version 只承担乐观并发语义 |
| 每连接快照历史占用过大 | 历史有界；共享不可变全局投影；连接只保存必要可见集和基线元数据；用 R4 记录真实 RSS |
| 任意 PropertyBag 导致帧膨胀 | `ProjectionPolicy` 字段白名单、类型/数量/字符串上限和频率分档 |
| 慢客户端拖垮扇出 | 状态/可靠队列分离、状态合并、重新同步和有界断开 |
| WebTransport C++ 生态变化 | 传输接口隔离；先完成 Beast WebSocket；后续只经文档评审接入成熟库 |
| 网络命令破坏确定性 | 只在 tick 边界进入命令缓冲；记录服务器序列和目标 tick；网络线程不直接写世界 |
| 把连接 ID 当 WID | 使用独立强类型；AOI 连接状态不复用 `AoiManager` 的观察者 WID |
| schema 演进破坏旧客户端 | 明确 protocol/schema 版本，FlatBuffers 只追加字段，保留 verifier 和旧 fixture 兼容测试 |
| 三方下载或构建失败 | 继续解决 vcpkg/镜像/overlay 问题；禁止改成自写协议、TLS 或序列化实现 |

## 阶段验收标准
